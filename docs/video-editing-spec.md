# 撮影動画の編集仕様

このリポジトリの本人用既定。根拠は [振り返り](video-editing-retrospective.md)。新しい指示がある項目だけ上書きし、回答済みの内容を毎回確認しない。製品の操作・証跡形式はインストール済みスキルに従う。

## 1. 着手と引き継ぎ

- ファイル番号の数値順で連結する。欠番・重複・順番の競合だけを確認する。
- 適用順は、最新の明示指示→案件内の合意済み設定→この本人用既定。参考動画・プロファイルは明示的に採用した項目へ適用し、他の指示を暗黙に上書きしない。
- 案件内の `decisions.json` 等へ、採用デザイン、辞書、カット方針、挿入画像の用途と開始・終了、適用理由を記録する。入力を変える際は製品の修正手順を使う。
- 音声を実際に聴けるか、動画を連続再生して見られるかを開始時に確認する。使えない能力は早めに短く説明し、可能な検査を続ける。同じ制約の承認を何度も求めない。
- 確認を求めるのは、矛盾する要望、素材だけでは確定できない名称・意味、ユーザー判断が必要な変更。通常の整文、同類不具合の修正、ローカル検査はまとめて進める。

## 2. 本人用のデザイン既定

| 対象 | 既定と検査 |
| --- | --- |
| 字幕書体 | M PLUS 1p Regular・400。明示選択があれば源暎ゴシック H-KLで全体を統一。実フォントファイルとレンダリングを確認し、文字単位の意図しないフォールバックや擬似太字を残さない |
| 字幕の見た目 | 白系の帯（`#f2f2f2`）・黒系文字（`#130e0f`）、同一サイズ・位置・ウェイト。青帯・黒帯・強調用別書体を混在させない |
| サイズ | 解像度と安全領域に合わせて案件で一度決め、全字幕に適用。長文だけ縮小せず整文・改行・表示区間で収める。見出しは役割ごとに固定し、字幕と同じ書体・通常ウェイトにする |
| 句読点 | 本文字幕の「。」「、」を削除。URLのピリオド、英語の記号、引用符、製品名の中点は一括削除しない |
| ロゴ | 支給ロゴの透過を保持。余計な背景パネルや色を足さず、実背景上で確認 |
| 見出し | 番号付きの列挙構成では主項目に `1.` から連番を付ける。導入・特典・まとめに機械的に連番を付けない |
| 画面接続 | 基本はそのままカットで接続。ワイプ、暗転、大型の章タイトル、装飾アニメーション、追加SEは明示採用した場合のみ |
| 支給画像 | 発話内容に対応する全区間を覆う静止表示。前後で意図しない撮影画面が1フレームだけ見えないよう境界を合わせる |

手元にないフォントは黙って別書体にせず、入手可否や明示された代替を確認する。参考分析の測定値は保持し、採用するデザインを案件設定側で絞る。

## 3. 意味が伝わる字幕と同期

1. 原音・撮影画面から内容を確かめ、全文を意味単位で読む。フィラー、無意味な繰り返し、言い直しを整理する。数値・主語・否定・条件・確信の程度を変えない。
2. 人名・サービス名・URL・検索語・ボタン名の案件辞書を作る。本人の訂正を全件へ反映する。未確定語は原音と画面を再確認し、なお不明なら候補をまとめて確認する。
3. 成功テイクを採用した音声へ字幕を同期させる。ASR時刻やDTW点は推定であり、音素の開始終了そのものとは扱わない。編集後の音声と出力時計で再照合する。
4. 助詞だけ、数詞と接尾辞、製品名やURLの途中で区切らない。全文URLは実画面で可読性と収まりを確認する。読めない長さなら表示時間や前後の文章を調整する。
5. 同じ発話中の数フレームだけの消灯・再表示は点滅候補として全件確認。次の文を先に出しすぎず、区切りとして必要な空白は残す。

例：「Blenderとかね あるので Goとかいろいろありますけども」→「BlenderとかGoとかいろいろあります」。ただし「たぶん」「対象外」など意味のある限定は消さない。映像中の誤発言を字幕だけで黙って訂正せず、ユーザーの訂正指示・確認済み画面など根拠を記録する。

## 4. 音声とカット

- 無音検出は候補作成に使う。素材のノイズ、息、語頭・語尾に合わせて境界を調整し、固定閾値だけで一括削除しない。音楽のある最終ミックスだけで発話の無音を判定しない。
- 言い直しは失敗テイクを除き、成功テイクが前後の文脈につながるよう残す。字幕を直すだけで噛んだ音声を放置しない。
- 語の波形・推定時刻の前後を確認し、弱い子音や語尾を守る。クリック除去用のフェードも語を削らない位置へ置く。聴ける場合は全接続点の前後を聴き、自然さを確認する。
- 字幕ごとに音声seek・再生開始を繰り返す構造を避ける。撮影音声は一つの編集マスター等で連続再生し、映像と同じ保持区間・尺を使う。
- 全素材境界、短い保持区間、章の前後を点検する。無言の前素材末尾だけが戻る「小島」、冒頭BGM前の不要な空白、末尾の残留無音を見逃さない。
- 映像の未配置・意図しない重複、白黒画面、読み込み画面、挿入画像の端を確認する。黒画素検出だけでは明るい余計な画面や点滅を検出できない。

## 5. 修正の展開と版管理

指摘ごとに「指示／確認された版と時刻／字幕ID・元素材区間／原因／全編での同類候補／対応／再検査」を案件内に記録する。未視聴の後半も対象にする。例えば一つの青帯を指摘されたら全スタイル、一つの瞬間画面なら全接続点を調べる。

尺の変更時は出力時刻と元素材時刻の対応を更新し、字幕・見出し・画像・BGM・概要欄の目次へ反映する。再生成した音声・字幕画像はキャッシュから旧版が出ない識別子で参照する。ユーザーには新しい版と変更内容をまとめて提示する。

## 6. 初稿前・修正後の独立レビュー

主担当が直した版を、独立したサブエージェントへ渡す。本人は一視聴者としてのレビューを求めている。ユーザー確認をこちらの初回不具合検出工程にしない。

レビュアーへ渡すものは、対象版、実映像・音声、字幕とタイムライン、編集要件、指摘履歴。主担当の「合格」という結論を判断の根拠にさせない。レビューは読取専用で行い、修正は主担当が集約する。

| 範囲 | 確認方法と合格条件 |
| --- | --- |
| 全字幕 | 全文の整文・辞書・意味の区切り・表示時刻を確認。未確定語や条件の欠落を解消 |
| 全時間帯の映像 | 可能なら連続再生。加えて全編を覆うサンプル、全接続点と画像出入りの短い動画、長い字幕・長いURLを確認。フレーム間だけに現れる不具合に注意 |
| 音声 | 可能なら通し聴取し、全接続点も重点聴取。聴けない場合は波形・音量・無音・同期等を検査し、聴感は未確認として残す |
| 指摘の回帰 | 個別指摘と同類の全編確認を実施。修正による尺・表示・音声の新しい問題を解消 |

レビュー記録は、対象の入力ハッシュ、実映像のハッシュまたは版、方法、確認区間、問題時刻、重要度、判定、未確認事項を持つ。初稿で見つけた音切れ、意味の欠落、字幕の不統一、意図しない瞬間画面は提示前に直す。修正後は影響範囲を再検査し、全体的な不具合なら全編へ広げる。変更のない範囲を理由なく何度も再検査しない。

サブエージェントが使えない場合は独立レビュー未実施と記録する。機械検査や静止画抽出は聴取・連続視聴の代替合格にしない。必要な検査が実行できない場合は「確認用プレビュー・未確認範囲あり」として提示できるが、「全編問題なし」と報告しない。本人の視聴・承認は、エージェントの実施内容と分けて記録する。

## 7. 書き出しと納品

- 現在版のプレビュー確認と書き出し依頼を利用し、同じ版の承認を聞き直さない。追加編集で版が変わった時だけ承認対象を更新する。
- 製品クライアントのNode処理にも専用のHOME・Python・データ環境を渡す。リポジトリの `scripts/aivep.py` の `environment()` を利用できる。端末の共有Pythonに子プロセスを任せない。
- 長いレンダーは進捗・プロセス・出力更新を確認する。止まった場合は原因を確かめ、対象のレンダラーだけを停止する。分割する場合も入力版を固定し、フレームと音声サンプルの欠落・重複を検査し、結合点を実MP4で確認する。
- 最終MP4で全フレームのデコード、解像度・fps・総フレーム・音声尺、黒画面等の候補、同期、クリッピングと音量を確認する。音量の目標は案件に記録し、指標だけで聴感が自然と断定しない。
- 最終MP4の実映像で字幕、ロゴ、挿入画像、全カットと分割結合点を再確認する。プレビューだけを見た証跡や旧版の証跡を最終版へ流用しない。
- 製品の現在版に必要な証跡を記録し、`workflow.py validate --stage video` と、保存・終了の回答を記録した後の `workflow.py validate` を実行する。技術検査の成功と、全工程の完了を区別する。
- 納品は完成ファイルのリンク、尺・仕様、検査結果と未確認範囲を簡潔に伝える。目次を依頼されたら、元動画でなく完成版タイムラインから `00:00` 始まりで作る。
- 本人が「これで完了」と答えたら終了意思として扱う。未依頼のプロファイル保存を進めない。保存を求められた時は最終描画設定から候補を作り、初期参考の多種類スタイルが混入していないか確かめてから提示する。名前・保存項目・具体値・保存先を製品の手順に従って確認し、承認済みの候補だけを保存・復元検査する。既に明示された名前や内容は聞き直さない。
